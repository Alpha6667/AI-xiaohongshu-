# OpenClaw 到小红书闭环前端执行任务单

## 适用范围

本任务单承接以下两份产品文档：

1. `.monkeycode/docs/PRODUCT_FLOW_OPENCLAW_TO_XHS.md`
2. `.monkeycode/docs/XHS_DATA_SYNC_PRODUCT_FLOW.md`

目标是把前端需要交付的页面与交互补齐，保证网页端真正成为 OpenClaw 主链路的可视化确认台和数据查看台。

## 前端已经完成的部分

1. 已完成消息入口视角重构，首页、`/tasks`、`/accounts`、`/review`、`/dashboard`、`/posts` 已具备新产品叙事。
2. 已把真实 `/api/tasks`、`/api/posts`、`/api/dashboard` 主路径接到页面。
3. 已完成 `/review` 动作链路验收，支持保存、提交、通过、退回。
4. 已完成发布状态在 `/review`、`/dashboard`、`/posts/[id]` 的真实消费。
5. 已移除接口成功时对种子发布状态的大部分回退逻辑。

## 前端仍需补齐的能力

### 一. 统一“QQ 与网页操作同一对象”的表达

#### 目标

让用户在网页端清楚知道：OpenClaw 和网页端展示的是同一份内容，而不是两条独立流程。

#### 必须交付

1. 在 `/review` 和 `/posts/[id]` 明确展示：
   - 当前消息来源
   - 当前确认版文案
   - 当前确认版图片
   - 当前是网页确认还是 OpenClaw 最新确认
2. 页面上补一段轻量说明，明确“QQ 与网页共享同一份确认结果”。
3. 当 QQ 端更改选择后，网页端应立即能展示最新确认结果。

### 二. 补齐账号接入与登录态展示

#### 目标

让用户知道当前小红书账号是否已接入、是否需要重新登录、最近一次同步是否成功。

#### 必须交付

1. 在 `/accounts` 或等价入口展示：
   - 已接入 / 需重新登录 / 同步中 / 同步失败
   - 最近一次同步时间
   - 最近一次同步错误摘要
2. 为“重新接入小红书”预留清晰入口。
3. 不要把账号页做成纯静态运营卡片，要能表达真实连接状态。

### 三. 补齐作品数据同步展示

#### 目标

把“发布成功”升级成“发布后能持续看到真实数据”。

#### 必须交付

1. `/posts` 列表展示真实：
   - 点赞数
   - 收藏数
   - 评论数
   - 发布时间
   - 审核状态
2. `/posts/[id]` 详情展示：
   - 最近一次同步时间
   - 指标历史
   - 当前审核状态
   - 平台帖子链接或平台帖子标识
3. 提供“手动刷新数据”入口。
4. 当数据尚未同步成功时，显示明确空态，而不是继续展示演示数据。

### 四. 完整展示发布状态细分

#### 目标

让用户能区分“执行中”“平台审核中”“已发布”“审核未通过”“执行失败”。

#### 必须交付

1. 页面状态文案补齐：
   - 待交给 OpenClaw
   - 已交给 OpenClaw
   - 执行中
   - 平台审核中
   - 已发布
   - 审核未通过
   - 发布失败
2. `/dashboard` 与 `/posts/[id]` 保持同一套状态文案映射。
3. 不要直接把后端原始枚举裸露给用户。

### 五. 收口剩余回退逻辑

#### 目标

避免真实接口成功但页面仍偷偷展示种子账号或演示帖子。

#### 必须交付

1. 删除成功响应场景下的种子账号归属兜底。
2. 删除成功响应场景下的演示指标兜底。
3. 仅保留“接口彻底失败时的整页回退”作为最后兼容。

### 六. 登录体验预留

#### 目标

为“后台登录尽量等于小红书账号接入”预留前端产品入口。

#### 必须交付

1. 页面文案避免引导用户理解成“两套账号体系”。
2. 若存在登录页或账号入口，优先表达为：
   - 使用小红书进入工作台
   - 重新连接小红书
3. 不优先引入“单独绑定账号”的重心页面。

## 不属于前端当前轮的事情

1. 不负责 QQ 指令解析。
2. 不负责浏览器自动化。
3. 不负责后台数据同步调度。

## 前端完成标准

当以下条件成立时，可认为前端侧闭环完成：

1. 用户能在网页端清楚看到自己与 OpenClaw 操作的是同一份内容对象。
2. 用户能在网页端明确知道账号是否已接入、是否需要重新登录。
3. 用户能在帖子列表和详情页看到真实点赞、收藏、评论和审核状态。
4. 用户能手动触发刷新，并知道当前数据是什么时间同步的。
5. 真实接口成功时，页面不再依赖种子账号或演示数据兜底。
