# 2026-05-12 下一步优化计划

## 优先级 P0：生产可见性与部署确认

目标：确保用户当前看到的是最新前端和最新后端/OpenClaw 代码。

任务：

1. 生产服务器拉取 `260509-chore-add-final-archive` 最新提交。
2. 前端执行 `pnpm --dir frontend build`。
3. 重启前端服务。
4. 浏览器强制刷新或清理缓存。
5. 页面上增加当前部署 commit hash 或版本号。

验收：

1. 首页、任务中心、账号页、发布中心、帖子详情页显示最新 UI。
2. 详情页不再出现旧的“素材加载失败”文本。
3. 页面可看到人工验证错误的可读提示。

## 优先级 P1：发布安全与状态防护复验

目标：防止真实发布重复触发或状态污染。

任务：

1. 对已发布 `post_9100f36d13` 触发发布按钮时应被拦截。
2. 无真实 `platformPostId` 的帖子不能显示为已发布。
3. `publishing` 状态下重复点击应被后端或 OpenClaw 拦截。
4. 发布失败恢复流程必须通过后端 service/repository 方法。

验收：

1. 无重复小红书帖子。
2. 无模拟 `platformPostId`。
3. 状态和 OpenClaw publish-state 一致。

## 优先级 P1：运行监控与告警

目标：减少问题只能靠人工翻日志发现。

任务：

1. 增加 OpenClaw `/health` 展示真实发布、登录态、人工验证状态。
2. 后端增加最近一次 publish/metrics 错误摘要接口。
3. 前端增加系统状态提示区。
4. 对 `post_needs_manual_verification` 做明显提示。

验收：

1. 用户能从前端看出需要人工验证。
2. 用户能知道 OpenClaw 是否 healthy。
3. 用户能知道最近一次 metrics 刷新失败原因。

验收：

目标：让日常运营更顺手。

1. 任务中心增加筛选：待确认、待生成、失败、已完成。

验收：

1. 用户能快速找到今天最该处理的任务。
2. 用户能快速定位失败原因和下一步动作。
3. 多账号状态一眼可见。
