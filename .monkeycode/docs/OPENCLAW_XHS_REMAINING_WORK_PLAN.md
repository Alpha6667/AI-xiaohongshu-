# OpenClaw 到小红书剩余工作执行顺序表

## 文档目标

本文件用于把当前尚未闭环的能力按优先级排序，明确执行顺序、责任方、前置依赖与完成标志，避免团队并行时做错顺序或重复投入。

## 当前总体判断

基于现有进展，系统已经完成“QQ 入站、任务承接、生成结果承接、网页端真实消费、OpenClaw 发布 webhook、异步回写”这些基础能力。

当前距离最终目标还差三段关键闭环：

1. OpenClaw 侧真正把候选内容回发到 QQ，并承接 QQ 里的确认指令。
2. OpenClaw 侧真正完成小红书真实登录态与真实发布提交。
3. 后端与前端补齐“小红书作品数据回收与展示”链路。

## 优先级总览

### P0：必须先完成，否则主链路无法成立

1. OpenClaw 把候选文案和候选图片回发到 QQ。
2. OpenClaw 承接 QQ 中的“发这个 / 选图 / 选文案 / 查状态”指令。
3. OpenClaw 完成小红书真实登录态保存与复用。
4. OpenClaw 完成一次真实发布提交。

### P1：主链路完成后必须补齐，否则状态和产品语义不完整

1. 后端补齐 `under_review / rejected` 状态语义。
2. 后端补齐 OpenClaw 指令入站接口和统一确认对象写回。
3. 前端补齐“QQ 与网页共用同一份确认结果”的明确表达。
4. 前端补齐账号接入状态、登录态失效和最近同步状态展示。

### P2：发布后数据闭环，属于你后续最关心的数据价值部分

1. OpenClaw 拉取小红书作品列表与互动数据。
2. 后端保存作品数据、同步状态与指标历史。
3. 前端展示点赞、收藏、评论、审核状态和刷新入口。

### P3：收口优化项，不做也不影响最小闭环，但会影响产品完成度

1. 清理前端剩余成功响应下的演示兜底。
2. 优化“后台登录即账号接入”的产品入口表达。
3. 增加 OpenClaw 主动提醒模板与异常引导文案。

| 12 | P2 | 后端保存作品数据、同步状态与指标历史 | 后端 | 第 11 步可返回真实数据 | `/api/posts` 与详情接口可返回真实互动数据 |
| 13 | P2 | 前端展示点赞、收藏、评论、审核状态和手动刷新入口 | 前端 | 第 12 步字段可用 | 登录后台后可真实看到小红书数据 |
| 14 | P3 | 清理成功响应场景下的种子账号/演示数据兜底 | 前端 | 第 10、13 步主路径稳定 | 页面成功响应时不再偷用演示数据 |

## 按团队拆分的最优启动顺序

### OpenClaw 先做

1. 候选内容回发到 QQ。
2. QQ 指令承接。
3. 真实登录态保存与复用。
4. 一次真实发布提交。
5. 作品数据拉取。

原因：当前最大的真实阻塞点都在 OpenClaw 侧，不先解决，后端和前端补再多也只是半闭环。

### 后端第二批做

1. 统一确认对象读写接口。
2. OpenClaw 指令入站接口。
3. `under_review / rejected` 状态补齐。
4. 账号接入状态与同步元数据。
5. 作品互动数据与指标历史存储。

原因：这些能力都依赖 OpenClaw 真正开始发回 QQ 指令和真实平台结果，否则只能先写空壳。

### 前端最后收口

1. 同一确认对象表达。
2. 审核中/审核失败等状态细分展示。
3. 账号接入与同步状态展示。
4. 作品互动数据展示与刷新入口。
5. 删除剩余 fallback。

原因：前端主结构已经到位，当前不缺页面骨架，缺的是后端和 OpenClaw 给出稳定真实字段后做最后收口。

## 里程碑定义

### 里程碑 1：QQ 与网页双端确认闭环

达成条件：

1. QQ 能收到候选文案和候选图片。
2. 用户能在 QQ 中直接说“发这个”。
3. 网页端能同步看到相同确认结果。

### 里程碑 2：真实小红书发布闭环

达成条件：

1. OpenClaw 有可复用小红书登录态。
2. 已完成一次真实提交。
3. backend 能区分执行中、审核中、已发布、审核未通过、执行失败。
4. 网页端与 QQ 都能收到一致结果。

### 里程碑 3：发布后数据回收闭环

达成条件：

1. 登录后台后可看到该小红书账号的真实作品数据。
2. 能看到点赞、收藏、评论、发布时间、审核状态。
3. 登录态失效或同步失败时，系统能明确提醒。

## 当前不建议优先做的事情

1. 不要先扩多账号调度。
2. 不要先扩批量发布。
3. 不要先扩复杂重试系统。
4. 不要先做完整运营报表。
5. 不要在 OpenClaw 真实链路没跑通前大量打磨纯展示 UI。

## 推荐本周执行顺序

### 第一组

1. OpenClaw：候选内容回发 QQ
2. OpenClaw：QQ 指令承接
3. 后端：统一确认对象写回接口

### 第二组

1. OpenClaw：真实登录态复用
2. OpenClaw：真实发布提交
3. 后端：补 `under_review / rejected`
4. 前端：补审核中/审核失败状态展示

### 第三组

1. OpenClaw：作品与互动数据拉取
2. 后端：保存同步状态与指标历史
3. 前端：展示点赞、收藏、评论与刷新入口
