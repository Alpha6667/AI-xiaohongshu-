# 前端下一阶段重做指令

## 重做目标

上一版正式后台框架已经完成。下一阶段不要继续只围绕“单账号后台发帖”做细化，而是要升级成真正符合用户使用方式的产品：

**OpenClaw 对话入口 + 后台确认 + 多账号运营**

产品真实闭环应调整为：

`给 OpenClaw 发消息下达发帖需求 -> OpenClaw 返回候选文案和图片 -> 用户回后台确认 -> 指定发布账号 -> OpenClaw 代发到小红书 -> 平台审核回写 -> 后台查看帖子和互动数据`

## 本阶段核心变化

- 后台不再是唯一入口。
- OpenClaw 对话应成为真实起点。
- 后台主要负责：
  - 接住消息任务
  - 确认内容
  - 选择账号
  - 查看发布结果
  - 查看帖子与数据
  - 管理多个账号

## 页面结构要求

下一阶段至少应重构或新增以下页面：

### 1. 总览首页

首页第一屏优先回答：

- 今天通过 OpenClaw 收到了哪些发帖任务
- 哪些任务已经生成候选内容
- 哪些任务还在等用户确认
- 今天有哪些账号在执行发布任务
- 最近已发布内容结果怎么样

首页不应再只围绕单账号看板组织。

### 2. 消息任务中心

这是新阶段新增的核心页面，必须能体现：

- 用户给 OpenClaw 发过什么消息
- 每条消息生成了什么发帖任务
- 当前任务进度到哪一步
- 是否已经生成文案
- 是否已经生成图片
- 是否需要用户回后台确认

消息任务中心应该成为“聊天入口”和“后台操作”之间的桥梁。

### 3. 多账号运营页

必须新增一个明确的多账号页面，而不是把账号信息塞进设置页：

- 已接入哪些小红书账号
- 哪个账号在线，哪个账号离线
- 每个账号今天有什么任务
- 每个账号最近表现如何
- 哪个账号当前需要用户关注

页面重点是“多个账号同时运营”，不是单纯展示账号列表。

### 4. 内容确认台

原来的发帖工作台要升级成“确认台”：

- 某个消息任务对应的主题
- OpenClaw / AI 返回的候选文案
- 候选图片
- 当前选择的发布账号
- 最终预览
- 确认交给 OpenClaw 执行

这里的重点不再只是“输入主题”，而是“确认系统已经生成好的内容并指定由哪个账号去发”。

### 5. 发布中心

发布中心继续保留，但强调：

- OpenClaw 是否已接收最终内容
- 是否已上传到小红书
- 是否提交审核
- 是否审核通过
- 若失败，是限流、审核未通过还是其他失败类型
- 对失败给出下一步动作建议

### 6. 帖子与数据页

帖子和数据页继续保留，但要加强多账号视角：

- 哪个账号发了哪条帖子
- 帖子链接
- 发布时间
- 点赞、收藏、评论等数据
- 哪类内容值得继续做

## 交互要求

- 页面默认中文。
- 不要继续保留大面积英文技术文案。
- “消息 -> 任务 -> 内容确认 -> 发布 -> 数据”这条链路必须一眼可懂。
- 多账号切换和当前账号归属必须明确可见。
- 候选文案、候选图片、当前发布账号都要有明显选中态。
- 发布成功后应能直接查看帖子；失败后应明确是回内容确认台还是等待重试。

## 不要这样做

- 不要继续只按单账号后台思路补细节。
- 不要把 OpenClaw 仅当成一个后端执行器，页面上要体现它是用户真实发起需求的入口。
- 不要把多账号能力藏进设置页或低优先级入口。
- 不要只堆状态卡，要体现任务来源、账号归属和操作流转。
