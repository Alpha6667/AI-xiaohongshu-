# 前端页面重做指令

## 重做目标

当前前端虽然已经完成第六轮联调闭环，但页面表达仍然偏开发联调后台，不符合真实使用场景。下一步前端重做目标不是继续补接口，而是把页面重构成一个真正可用的“小红书 AI 发帖工作台”。

产品核心闭环必须围绕以下链路展开：

`账号接入 -> 输入主题 -> AI 生成文案和图片 -> 人工挑选 -> OpenClaw 代发 -> 审核通过 -> 查看帖子和点赞数据`

## 总体要求

- 页面必须默认中文，不要继续保留英文开发态文案。
- 页面应更像正式后台产品，而不是演示性质的技术工作台。
- 信息组织要围绕用户真实操作顺序，而不是围绕后端接口命名。
- 视觉上保持高级感，但不要做传统模板后台，也不要做过度花哨的大屏。
- 本轮重点是重构页面结构、内容表达和交互路径，不是扩后端接口。

## 页面结构要求

至少重做以下 4 个核心页面：

### 1. 总览首页

首页第一屏应优先回答这几个问题：

- 当前正在使用哪个小红书账号
- OpenClaw 当前是否已连接、是否可发帖
- 今天准备发什么主题
- AI 是否已经生成候选文案和候选图片
- 最近一条发布内容是否审核通过
- 最近已发布帖子是否可直接查看链接和数据

首页不应以抽象统计卡为主，而应以“今天要做什么”和“最近结果怎么样”为主。

### 2. 发帖工作台

这是核心页面，必须按真实使用顺序组织：

- 输入今天想发的主题
- 展示 AI 生成的 3 版候选文案
- 展示 AI 生成的候选图片
- 支持用户明确选择最终文案和最终图片
- 展示手机里的最终发布预览效果
- 提供“重新生成一版”“确认这版并去发布”等清晰动作

不要把工作台做成空白编辑器；它应更像 AI 已经先帮用户出好方案，用户只做选择和微调。

### 3. 发布中心

发布中心必须明确展示 OpenClaw 执行链路：

- 是否已接收最终文案和图片
- 是否已上传到小红书
- 是否已提交审核
- 当前是否在等待平台审核
- 是否已审核通过
- 若失败，是限流、审核未通过还是其他失败类型
- 下一步建议动作是什么

不要只显示 `publishing` 或 `failed` 这种技术状态；页面必须让用户看懂“现在卡在哪”和“接下来该做什么”。

### 4. 帖子与数据页

帖子和数据页必须更贴近用户真实关心内容：

- 已审核通过的帖子列表
- 帖子发布时间
- 小红书帖子直达链接
- 点赞、收藏、评论等核心数据
- 对表现好的内容给出继续复用的建议

不要把这页做成只有内部状态列表的后台页。

## 具体交互要求

- 所有关键按钮文案统一中文。
- 失败分类必须用用户能理解的中文表达，不要直接裸露英文枚举。
- 工作台中“候选文案”和“候选图片”必须有明显选中态。
- 发布成功后应能直接进入帖子详情或帖子数据查看路径。
- 审核未通过时，页面要明确建议回到工作台改文案还是改图片。

## 不要这样做

- 不要继续保留大面积英文后台文案。
- 不要把页面主逻辑建立在接口字段名解释上。
- 不要继续让首页看起来像普通数据看板。
- 不要为了好看牺牲真实操作路径。
- 不要在本轮擅自扩展新业务边界，如多账号权限系统、定时发布复杂编排等。

## 原型参考

请以前端重做时参考以下静态原型：

- `product-prototype/index.html`
- `product-prototype/composer.html`

- `product-prototype/posts.html`

这些原型不是最终视觉稿，但页面结构、业务顺序和信息表达方向要尽量贴近。
