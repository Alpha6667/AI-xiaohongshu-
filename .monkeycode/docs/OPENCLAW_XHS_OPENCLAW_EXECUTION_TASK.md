# OpenClaw 到小红书闭环 OpenClaw 执行任务单

## 适用范围

本任务单承接以下两份产品文档：

1. `.monkeycode/docs/PRODUCT_FLOW_OPENCLAW_TO_XHS.md`
2. `.monkeycode/docs/XHS_DATA_SYNC_PRODUCT_FLOW.md`

目标是明确 OpenClaw 侧在“QQ 对话入口 -> 候选内容回发 -> 指令确认 -> 小红书执行发布 -> 数据回收提醒”中的责任。

## OpenClaw 已经完成的部分

1. 已完成 QQ 对话接入。
2. 已完成 QQ 消息转发到 backend。
3. 已提供 `POST /api/openclaw/publish` webhook。
4. 已支持 Bearer Token 鉴权。
5. 已支持异步发布结果回写 backend。
6. 已安装 Chrome / Playwright，并已能真实访问小红书页面。
7. 已验证当前真实阻塞点是“小红书账号尚未在执行环境里完成登录”。

## OpenClaw 仍需补齐的能力

### 一. 把生成结果回发到 QQ

#### 目标

让用户在 QQ 里真实看到后台生成的候选文案和候选图片，而不是只有网页端有内容。

#### 必须交付

1. 从 backend 拉取或接收当前任务对应的候选文案。
2. 从 backend 拉取或接收当前任务对应的候选图片。
3. 把候选文案和候选图片以 QQ 可消费的形式发给用户。
4. 回发消息中要附带足够标识，便于后续用户说“发这个”时可定位到同一 `postId`。

### 二. 承接 QQ 确认指令

#### 目标

支持用户在 QQ 中直接说“发这个”“用第 2 张图”“看一下结果”。

#### 必须交付

1. 至少支持以下指令意图：
   - 发布当前确认版
   - 选择候选图
   - 选择候选文案
   - 查询当前状态
   - 刷新作品数据
2. 将解析后的结果回写到 backend 统一对象，而不是仅在 OpenClaw 本地保留状态。
3. 对不明确指令返回引导，而不是直接误发。

### 三. 完成真实发布登录态闭环

#### 目标

让 OpenClaw 执行环境真正具备小红书可复用登录态。

#### 必须交付

1. 完成一次真实扫码登录。
2. 保存并复用登录态。
3. 重新打开浏览器后仍可进入发布页而不跳登录。
4. 当登录态失效时，能检测并回传 `reauth_required` 类结果。

### 四. 完成真实发布最小闭环

#### 目标

不再停留在模拟发布，要真正把确认后的文案和图片提交到小红书。

#### 必须交付

1. 使用真实浏览器自动化把标题、正文、标签和图片填入小红书发布页。
2. 触发实际提交。
3. 区分以下结果：
   - 执行失败
   - 已提交等待审核
   - 审核通过已发布
   - 审核未通过
4. 通过同步响应和异步回写把结果传给 backend。
5. 在需要时返回执行日志 `executionLogs`。

### 五. 增加数据回收能力

#### 目标

让 OpenClaw 不只负责发布，还能帮助拉回小红书真实作品与互动数据。

#### 必须交付

1. 在登录态有效前提下，进入创作者中心或等价页面拉取作品列表。
2. 读取至少以下字段：
   - 平台作品 ID
   - 标题
   - 发布时间
   - 点赞数
   - 收藏数
   - 评论数
   - 审核状态或发布状态
3. 将数据回写 backend。
4. 当拉数失败时，回写同步失败原因，而不是伪装成发布失败。

### 六. 双端通知

#### 目标

让 QQ 端真正成为提醒入口，而不只是消息入口。

#### 必须交付

1. 生成完成后通知用户查看候选内容。
2. 发布开始后通知用户已进入发布流程。
3. 已提交平台后通知用户等待审核。
4. 审核通过后通知用户已发布。
5. 审核未通过、发布失败、登录态失效、同步失败时主动提醒用户。

## 不属于 OpenClaw 当前轮的事情

1. 不负责定义网页端 UI。
2. 不负责后端对象模型设计。
3. 不负责前端展示层兜底逻辑。

## OpenClaw 完成标准

当以下条件成立时，可认为 OpenClaw 侧闭环完成：

1. 用户在 QQ 中能收到后台生成的文案和图片。
2. 用户在 QQ 中能直接选择内容并触发发布。
3. OpenClaw 已具备可复用小红书登录态。
4. OpenClaw 能完成一次真实提交，并把结果稳定回写 backend。
5. OpenClaw 能在登录态有效时拉回作品互动数据，并把关键状态主动通知到 QQ。
