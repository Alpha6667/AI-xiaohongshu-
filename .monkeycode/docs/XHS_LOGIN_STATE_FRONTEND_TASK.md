# 小红书登录态策略前端执行任务单

## 适用文档

本任务单承接：

1. `.monkeycode/docs/XHS_LOGIN_STATE_STRATEGY.md`
2. `.monkeycode/docs/XHS_DATA_SYNC_PRODUCT_FLOW.md`

## 目标

让前端能清楚表达“小红书账号是否已连接、是否需要重新登录、最近一次验证是否成功”，并把复杂技术细节隐藏在产品化表达之后。

## 前端当前已具备的基础

1. 已有 `/accounts` 多账号运营页。
2. 已有 `/dashboard`、`/posts`、`/posts/[id]` 等页面可展示账号上下文。
3. 已有多账号和消息任务主叙事框架。

## 本轮必须交付

### 1. 展示账号连接状态

在 `/accounts` 或等价页面展示至少以下信息：

1. 已连接
2. 需要重新登录
3. 未连接
4. 验证中

同时展示：

1. 最近一次验证时间
2. 最近一次错误摘要（若有）

### 2. 提供明确入口

至少提供以下产品入口之一：

1. `连接小红书`
2. `重新连接小红书`

要求：

1. 不把入口写成技术术语。
2. 不让用户理解成要自己处理 cookies 或浏览器状态。

### 3. 在发布相关页面展示账号可用性

在以下页面增加账号可用性提示：

1. `/review`
2. `/dashboard`
3. `/posts/[id]`

要求：

1. 若当前账号 `reauth_required`，明确提示不能继续真实发布。
2. 若当前账号未连接，明确提示先连接小红书。

### 4. 在数据页展示同步受阻原因

在帖子页或账号页中，当数据拉取因登录态失效而不可用时：

1. 显示“需要重新登录小红书后才能同步最新数据”。
2. 不要继续展示误导性的假同步成功结果。

### 5. 统一文案

推荐文案：

1. `连接小红书`
2. `已连接`
3. `连接已失效，请重新登录`
4. `最近一次验证成功于 ...`

不要使用：

1. `导入 cookies`
2. `上传 storageState`
3. `会话同步失败`

### 6. 收口回退逻辑

要求：

1. 如果接口明确返回 `reauth_required`，页面不能继续假装账号可用。
2. 如果接口明确返回未连接，页面不能继续展示“已连接”的演示状态。

## 本轮不要做

1. 不负责浏览器登录流程实现。
2. 不负责后端状态机设计。
3. 不负责 OpenClaw QQ 提醒逻辑。

## 完成标准

当以下条件成立时，可认为前端侧任务完成：

1. 用户能在账号页一眼看懂当前小红书账号是否可用。
2. 用户能在发布页明确知道是否需要重新登录。
3. 用户能在数据页明确知道为什么当前无法同步最新数据。
4. 页面文案不再暴露底层技术细节。
