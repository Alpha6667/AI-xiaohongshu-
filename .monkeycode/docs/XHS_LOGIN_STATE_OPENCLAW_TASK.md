# 小红书登录态策略 OpenClaw 执行任务单

## 适用文档

本任务单承接：

1. `.monkeycode/docs/XHS_LOGIN_STATE_STRATEGY.md`
2. `.monkeycode/docs/OPENCLAW_XHS_REMAINING_WORK_PLAN.md`

## 目标

让 OpenClaw 侧真正承担小红书登录态的建立、保存、复用、失效检测和续期触发工作，成为真实发布与真实拉数的统一执行入口。

## OpenClaw 当前已具备的基础

1. 已安装 Chrome / Chromium。
2. 已安装 Playwright。
3. 已能访问小红书创作者中心页面。
4. 已具备发布 webhook 和异步回写能力。

## 本轮必须交付

### 1. 实现首次接入流程

要求：

1. OpenClaw 能打开小红书登录页。
2. 支持用户通过扫码或手机号验证码完成登录。
3. 登录成功后能验证是否已进入创作者中心。

### 2. 保存登录态

至少实现以下之一：

1. 保存 Playwright `storageState`
2. 或保存等价浏览器会话快照

要求：

1. 登录态按账号隔离保存。
2. 不跨账号复用。
3. 保存后可被后续发布和拉数流程复用。

### 3. 发布前验证登录态

要求：

1. 每次真实发布前先加载已保存登录态。
2. 打开创作者中心或发布页做轻量验证。
3. 若已失效，停止执行并回写“需要重新登录”。

### 4. 拉数前验证登录态

要求：

1. 每次拉作品或互动数据前先验证登录态。
2. 若已失效，停止执行并回写“需要重新登录”。

### 5. 失效检测与回写

当出现以下任一情况时，视为登录态失效：

1. 被跳转到登录页。
2. 页面出现扫码/验证码登录要求。
3. 创作者中心关键页面无法访问且提示未登录。

要求：

1. 立即回写 backend 账号状态。
2. 不继续盲目重试真实发布。
3. 不把该错误混写成普通发布失败。

### 6. 支持重新连接

要求：

1. 当用户重新扫码或验证码登录成功后，覆盖旧登录态。
2. 回写 backend 为 `connected`。
3. 恢复真实发布与拉数能力。

### 7. 提示能力

至少支持以下提醒：

1. `请完成扫码登录，成功后我会继续发布。`
2. `当前小红书登录状态已失效，需要重新登录。`
3. `小红书账号已连接，可以继续发布和查看数据。`

## 本轮不要做

1. 不负责前端账号页设计。
2. 不负责后端聚合字段定义。
3. 不负责多账号调度。

## 完成标准

当以下条件成立时，可认为 OpenClaw 侧任务完成：

1. 用户能完成一次真实扫码或验证码接入。
2. 登录态保存后可复用。
3. 重开浏览器后仍可进入创作者中心。
4. 发布前和拉数前都能先校验登录态。
5. 失效时能明确回写并提示重新登录。
