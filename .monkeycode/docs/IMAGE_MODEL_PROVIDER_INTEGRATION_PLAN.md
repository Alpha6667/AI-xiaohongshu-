# 生图模型厂商接入与配置页方案

## 目标

为项目补齐一套可扩展的生图模型接入能力，让用户后续可以在网页端：

1. 选择生图 API 厂商
2. 填写或更换 API Key
3. 自动切换该厂商的默认图片模型
4. 用同一套后端接口驱动真实图片生成

## 当前约束

1. 当前仓库里的 `generate-images` 已有接口，但仍是占位实现，不是真实调用第三方模型。
2. 当前用户还没有真实可用的 API Key。
3. 因此本轮重点不是立刻打通真实出图，而是先把“配置能力、厂商抽象、默认模型映射、无 Key 时的产品表达”搭起来。

## 推荐首批支持厂商

### 国外

1. OpenAI
   - 默认模型：`gpt-image-1`
2. Black Forest Labs
   - 默认模型：`flux.2`
3. Stability AI
   - 默认模型：以后端最终接入时确认当前稳定型号为准

### 国内

1. 火山方舟
   - 默认模型：以 `Seedream` 当前稳定型号为准
2. 腾讯混元
   - 默认模型：以混元生图当前稳定型号为准
3. 阿里云通义万相
   - 默认模型：以万相当前稳定型号为准

## 产品原则

1. API Key 不应直接在浏览器端拿去调用第三方模型。
2. 前端允许录入 Key，但读取时只返回脱敏值，例如 `sk-****abcd`。
3. 前端只负责配置输入、脱敏展示、厂商切换和测试触发。
4. 真正的模型调用必须由后端发起。
5. 当前没有 Key 时，页面应明确展示“尚未配置，可先完成厂商和模型设置”。

## 厂商切换规则

当用户切换厂商时，系统应自动带出对应默认模型。

建议内置映射：

1. `openai -> gpt-image-1`
2. `bfl -> flux.2`
3. `volcengine -> seedream`
4. `tencent -> hunyuan-image`
5. `alibaba -> wanx`

说明：

1. 页面默认先带出系统推荐模型。
2. 用户仍可手动改成该厂商下的其他模型名。
3. 最终精确模型名由后端接入该厂商时按官方文档校准。

## 无 Key 阶段也必须先完成的能力

### 前端

1. 模型设置页 UI
2. 厂商切换
3. Key 输入和脱敏展示
4. 默认模型自动切换
5. “未配置 Key” 空态与提示文案

### 后端

1. 模型厂商配置数据结构
2. 配置读取与保存接口
3. Key 脱敏返回逻辑
4. 厂商到默认模型的服务端映射
5. 无 Key 时的统一错误语义，例如 `provider_not_configured`

## 建议页面入口

建议新增单独页面：

1. `/settings/models`

页面至少包含：

1. 厂商选择
2. API Key 输入框
3. 默认模型输入或下拉
4. Base URL 可选输入
5. 测试连接按钮
6. 保存按钮

## 当前阶段边界

1. 本轮不要求前后端必须完成所有厂商的真实 API 对接。
2. 本轮优先把架子搭好，真实模型调用建议先做一到两家。
3. 如果没有 Key，`generate-images` 不必假装成功出图，应返回明确“未配置模型厂商”的可读结果。

## 本轮建议分工

1. 前端先完成模型设置页与交互。
2. 后端先完成配置接口、默认模型映射和无 Key 语义。
3. 真实出图优先接入：
   - `OpenAI`
   - `火山方舟`

## 交付结果预期

即使当前没有 Key，本轮完成后也应达到：

1. 用户可以在网页端选厂商、填 Key、切默认模型。
2. 系统不会把 Key 明文暴露到页面读取接口。
3. 前后端已为后续真实接入 OpenAI / 火山方舟留出稳定边界。
4. 等用户后续拿到 Key 后，只需要补最小真实厂商调用逻辑即可开始联调。
