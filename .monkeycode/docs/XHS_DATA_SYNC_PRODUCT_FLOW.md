# 小红书账号数据拉取产品流程

## 文档目标

本文件用于统一前端、后端与 OpenClaw 对“小红书账号接入后自动拉取作品与数据表现”的产品理解，明确登录后台、账号接入、数据同步和展示之间的关系。

## 一句话定义

用户登录后台并完成小红书账号接入后，系统应自动拉取该账号的作品列表、点赞、收藏、评论、审核状态和发布时间等信息，并在网页端和必要时通过 OpenClaw 向用户展示最新结果。

## 产品目标

1. 用户进入后台后，可以直接看到当前小红书账号的作品和数据表现。
2. 用户不需要再单独执行复杂的“绑定账号”操作。
3. 系统应尽量把“账号接入”和“数据可见”合并为一次连贯体验。
4. 发布后的作品数据应可持续同步，而不是只记录首次发布结果。

## 核心原则

1. “登录后台”与“拉取小红书数据”在用户体验上可以是一体化流程。
2. 系统内部仍需具备独立的小红书登录态或可用授权存储能力。
3. 只有在账号接入有效时，系统才能自动拉取小红书数据。
4. 数据展示应以真实同步结果为准，不应长期依赖前端种子数据或假数据。
5. 发布链路和数据回收链路应共用同一个账号身份，不应发布用一个账号、拉数用另一个账号。

## 用户视角流程

### 1. 登录与进入后台

1. 用户进入后台。
2. 用户完成登录。
3. 如果当前产品采用“小红书登录即后台登录”的模式，系统在登录后直接识别当前小红书账号。
4. 如果当前产品采用“后台登录 + 自动接入小红书”的模式，系统应在首次登录后自动完成接入，不额外要求用户理解复杂绑定步骤。

### 2. 账号接入确认

1. 系统确认当前用户对应的小红书账号是否已具备可用登录态。
2. 如果登录态有效，系统进入自动拉数流程。
3. 如果登录态无效，系统提示用户重新接入或重新登录小红书。

### 3. 自动拉取数据

1. 系统自动拉取该小红书账号的作品列表。
2. 系统自动拉取每篇作品的基础信息与表现数据。
3. 系统将数据写回后台统一数据模型。
4. 网页端自动展示最新结果。

### 4. 数据查看与刷新

1. 用户可在网页端查看作品列表。
2. 用户可查看单篇作品的点赞、收藏、评论和发布时间。
3. 用户可查看作品是否仍在审核中、已发布或被驳回。
4. 用户可手动刷新，也可由系统自动定时同步。

### 5. 异常提醒

1. 如果账号登录态失效，系统需提醒用户重新登录。
2. 如果数据同步失败，系统需记录失败原因。
3. 若有必要，OpenClaw 也可通过 QQ 提醒用户“数据同步失败”或“账号需要重新登录”。

## 需要拉取的核心数据

### 账号级信息

1. 账号标识
2. 账号名称
3. 当前登录态是否有效
4. 最近一次成功同步时间

### 作品级信息

1. 平台作品 ID
2. 标题
3. 封面或主图
4. 发布时间
5. 当前平台状态
6. 审核状态
7. 作品链接或可访问入口

### 指标级信息

1. 点赞数
2. 收藏数
3. 评论数
4. 需要时可扩展阅读量、曝光量或转发量

## 推荐状态语义

为避免前后端对状态理解不一致，建议至少统一以下语义：

1. `connected`：账号已接入且登录态有效。
2. `reauth_required`：账号登录态失效，需要重新登录。
3. `sync_pending`：等待同步。
4. `syncing`：正在拉取数据。
5. `sync_success`：同步成功。
6. `sync_failed`：同步失败。
7. `under_review`：作品已提交平台，仍在审核。
8. `published`：作品已审核通过并发布。
9. `rejected`：作品审核未通过。

## 展示要求

### 网页端

1. 在账号页展示当前账号是否已接入、最近同步时间和同步状态。
2. 在帖子列表页展示作品标题、发布时间、点赞、收藏、评论和状态。
3. 在帖子详情页展示更完整的指标历史、发布记录和审核结果。
4. 如果当前数据来自真实同步结果，页面不应再展示回退假数据提示。

### OpenClaw / QQ

1. 在用户主动询问时，OpenClaw 可返回最近几篇作品的数据摘要。
2. 当出现登录态失效或同步异常时，OpenClaw 可主动提醒。
3. 当某篇作品审核通过或数据表现明显变化时，OpenClaw 可提供简短通知。

## 系统分工

### 对后端

1. 维护账号接入状态、登录态有效期和同步时间。
2. 提供作品列表和作品详情的数据接口。
3. 负责保存每次同步得到的作品信息和指标快照。
4. 负责区分“发布成功”和“数据同步成功”这两类不同事件。

### 对 OpenClaw

1. 在需要时协助完成账号登录态建立或续期。
2. 在需要时负责通过浏览器执行环境拉取小红书页面数据。
3. 将同步异常或关键结果通知给用户。

### 对前端

1. 负责展示账号接入状态和作品数据。
2. 负责让用户清楚看到当前数据是何时同步的。
3. 负责提供刷新入口、异常提示和历史数据查看能力。

## 与发布链路的关系

1. 发布链路负责把内容提交到小红书。
2. 数据同步链路负责把平台上的真实结果拉回后台。
3. 两条链路都应围绕同一个小红书账号工作。
4. 用户感知上应表现为一个完整闭环：发布后自动看到真实表现数据。

## 当前范围边界

1. 当前优先验证单账号数据拉取。
2. 当前优先拉取作品列表与核心互动指标，不先扩全量运营报表。
3. 当前不扩复杂权限系统。
4. 当前不扩多账号聚合分析面板。
5. 当前允许以手动刷新加最小自动同步作为第一阶段方案。

## 验收口径

当以下条件同时成立时，可认为该能力成立：

1. 用户登录后台后，系统能识别当前小红书账号是否已接入。
2. 登录态有效时，系统能自动拉取该账号的作品列表。
3. 系统能展示至少点赞、收藏、评论、发布时间和作品状态。
4. 登录态失效时，系统能明确提示重新接入。
5. 数据同步结果可在网页端稳定展示，并与真实账号状态一致。
