# 前端信息架构清爽化任务书

## 背景

当前后台页面信息密度高，说明文字过长，状态重复，卡片占用空间偏大。用户希望页面更一目了然，把解释性内容收进小问号 tooltip，默认界面只保留状态、数据和动作。

## 改版范围

1. 首页
2. 消息任务中心
3. 多账号运营
4. 发布中心
5. 帖子详情页
6. 左侧导航和通用卡片样式

## 总体原则

1. 页面正文只保留关键状态、关键数据、下一步动作。
2. 长说明文案改为小问号 tooltip。
3. 任务卡默认只显示标题、账号、主状态、时间、下一步动作。
4. 详细信息放入展开区或详情页。
5. 合并重复状态，页面只突出一个主状态。
6. 异常、失败、待处理内容优先展示。
7. 已完成内容降低视觉权重。
8. 保持真实发布、metrics、图片展示、素材展示能力不回退。
9. 保持当前米白和黑色视觉风格。

## 新增通用组件

### HelpTip

用途：承载说明类文案。

要求：

1. 使用小问号图标或文本按钮展示。
2. 支持 hover 和 focus 显示。
3. 支持键盘访问。
4. 移动端可点击显示。
5. tooltip 文案简短，避免整段说明占据页面。

### CompactStatus

用途：统一状态颜色和状态文本。

状态类型：

1. 流程状态：待生成、待确认、待发布、发布中、已发布、失败。
2. 账号状态：在线、需登录、同步异常、未知。
3. 数据状态：未拉数、同步成功、同步失败。

颜色建议：

```text
成功 = 绿色
处理中 = 蓝色
等待 = 灰色
警告 = 橙色
失败 = 红色
```

### CollapsibleDetails

用途：默认收起低频信息。

可放内容：

1. OpenClaw 回写。
2. 平台结果。
3. 错误详情。
4. 素材详情。
5. 原始消息。

## 页面调整

### 首页

改成今日工作台。

首屏展示：

1. 待确认数量。
2. 待生成数量。
3. 发布中数量。
4. 失败数量。

主操作按钮：

1. 去确认。
2. 处理失败。
3. 查看发布中。

链路说明改成紧凑步骤条：

```text
消息进入 -> 生成内容 -> 人工确认 -> OpenClaw 发布 -> 数据复盘
```

首页任务列表只展示最重要的 3 条。

### 消息任务中心

任务展示改成紧凑列表。

默认列：

1. 标题或来源消息。
2. 账号。
3. 状态。
4. 素材状态。
5. 计划时间。
6. 下一步。

按钮：

1. 去确认。
2. 生成内容。
3. 查看详情。

详细状态放入 `CollapsibleDetails`。

### 多账号运营

改成账号健康看板。

默认列：

1. 账号。
2. 登录态。
3. 今日任务。
4. 待处理。
5. 已发布。
6. 最近同步。
7. 操作。

异常账号优先展示。账号状态说明放入 `HelpTip`。

### 发布中心

改成发布队列。

默认展示：

1. 标题。
2. 账号。
3. 主状态。
4. 平台状态。
5. 素材。
6. 发布时间。
7. 下一步。

OpenClaw 回写和 noteId 放入展开详情。失败任务置顶。

### 帖子详情页

结构调整为：

1. 顶部状态条：标题、状态、platformPostId、刷新指标。
2. 内容预览区：图片或视频、文案、标签。
3. 发布结果区：发布时间、平台审核、OpenClaw 回写。
4. 数据表现区：最新指标和历史快照。

说明类字段放入 `HelpTip`：

1. `platformPostId`
2. 数据来源
3. 同步状态
4. 平台发布时间

## 样式要求

1. 减少大面积空白。
2. 降低卡片高度。
3. 数字指标更醒目。
4. 按钮体现明确操作入口。
5. 移动端不能横向溢出。
6. 桌面端列表优先，移动端卡片优先。

## 验收标准

1. 首页首屏能看到今天最该处理什么。
2. 消息任务中心是紧凑任务列表。
3. 多账号页面能看到账号异常和账号可用性。
4. 发布中心能区分失败、发布中、已发布。
5. 帖子详情页首屏能看到图片或视频、文案、标签和发布状态。
6. 长说明通过小问号 hover/focus 显示。
7. 真实发布、refresh metrics、图片展示不受影响。
8. `pnpm --dir frontend build` 通过。
9. 不提交 `.monkeycode/MEMORY.md`，除非是明确的项目行为规则更新。
